# Kouzlo bez dozoru: deterministic rules v2

`spark-v2` uses the [v1 physics](arcade-rules-v1.md), seeds, scoring
and replay format with two small difficulty changes. Ordinary gates after the
opening have a gap four logical pixels narrower. Their width is
`max(84, 148-floor(i/5)*4)` instead of `max(88, 152-floor(i/5)*4)`.
The first gate remains 168 pixels wide. Long corridors (`i%7==6`) retain
their v1 width `max(104, 152-floor(i/5)*4)` and height 72.

Horizontal movement and vertical scrolling are 10% faster. For completed tick
`t` (one based), move horizontally by `direction * (t%5==0 ? 3 : 2)` and set
scroll to `2*t+floor(t/5)`. Input still precedes movement and collision; the
60 Hz tick rate stays unchanged. Integer steps avoid replay drift. The run
still ends after 108000 ticks (30 minutes), so generate 1321 gates to cover
the longer travel distance. A maximum-duration v2 run clears 1320 gates.

The client explicitly requests `GET /app/v1/game/arcade?rulesVersion=spark-v2`
and includes `rulesVersion: 'spark-v2'` in the existing POST `/runs` body.
Omitting the version still selects v1 for released apps. An unsupported version
returns 409; reusing an issuance operation ID for another version also returns
409. The finish endpoint chooses the verifier from the stored ticket version.

Courses and records are separate for each rules version. The existing
`game_arcade_bests` table stays intact for v1; the additive
`game_arcade_bests_v2` table holds v2 records. Account deletion covers both.
No old scores are deleted or copied into the harder competition.
The client retains pending v1 submissions across an upgrade, but their receipts
cannot update the v2 standings. Practice records also use a versioned key.

Shared v2 fixtures are generated by
`node mobilni-aplikace/scripts/generate-spark-vectors.mjs`. Keep the existing
v1 fixtures unchanged: the backend verifies both versions. Maximum-duration
v2 witnesses use input decisions no more frequently than every 12 ticks
(200 ms), covering all corridors and the minimum gap.

Deploy the compatible backend before publishing the v2 app. A v2 app talking
to an old backend rejects its v1 ticket/standings and can still play practice.
An updated native app is required for the harder game and its narrow versioned
ranking route; older apps continue playing v1.
